01The idea

Arch gives you a great deal: a current system, an honest package manager and the best documentation in Linux. What it does not give you is a desktop. You are handed a console and the job of assembling one.

Hyprland is the same trade one level up. It is an excellent compositor and it ships almost no opinions — a bar, a launcher, notifications, a lock screen, idle handling, screenshots, clipboard history and audio are all separate programs you choose, install and wire together yourself. That assembly is the work, and it is much the same every time.

starch does the assembly. It boots a desktop that is already wired together, writes it to your disk, and leaves the system working the way Arch and Hyprland normally do.

starch is a starting point, not a layer. It sets the desktop up; it does not stand between you and the system afterwards.

02It does not take over

starch stays on the machine — the desktop it configured is yours to keep, change or throw away. What it does not do is replace how Arch and Hyprland already work:

No custom repository

Every package comes from the official Arch repositories.

No branding

/etc/os-release says Arch, because it is Arch.

No hooks or agents

Nothing runs that you did not put there. No self-updates.

No framework to learn

Updates are pacman -Syu, the same as any Arch install, and the Arch wiki is the documentation.

The desktop it leaves is a set of plain files you can read, edit or delete, with comments explaining what each choice does and why — a starting point you can learn from rather than a black box you maintain around. The configuration lands in ~/hyprland-setup, exactly where it would be if you had cloned it yourself. Keep it to re-run pieces later, or delete it; nothing depends on it being there.

Packages are still pacman's. Configuration is still Hyprland's own files. Nothing was wrapped, and nothing needs starch to keep running.

04Settings, without editing config files

Hyprland is configured in files, and that is the right answer right up until you want to change your display scale. starch ships starch-config, a settings app on SUPER + I, for the handful of things that are genuinely awkward to hand-edit: display scale, resolution and refresh rate, idle and lock timeouts, what the lid does, keyboard and touchpad behaviour, and the theme, wallpaper, cursor and font.

Nothing requires you to use it — these are Hyprland's own settings, in Hyprland's own files. It exists because a few of them are genuinely awkward to get right by hand, and it is careful about how it writes them.

It never edits your files

It owns three generated files outright and rewrites them whole, keeping the previous version as .bak. Nothing you wrote is touched.

It loses to you

Its settings load last, so they override the defaults without either file knowing about the other. Delete them and you are back to the shipped configuration.

It offers only what works

A display scale is legal only if it divides the resolution into whole pixels. Hyprland accepts any number and then quietly snaps to one that does — so a config can say 1.5 while the session runs at 1.6. The menu lists the scales that are actually legal for your mode.

Everything it writes is a plain text file next to the ones you edit yourself. The app is a convenience, not a layer — you can always open the file instead.

05How the install works

The ISO is a live desktop that installs itself. tty1 starts Hyprland, and the session starts the installer. That is not decoration: it is what gives the medium a network applet, a terminal and a file manager, so you can join a wifi network and check the machine works before committing a disk to it. An installer alone cannot do any of that.

Quitting the installer leaves the desktop running. Logging out, or a desktop that will not start at all, falls through to a text menu with the older installer, a shell and this boot's log.

The installer copies the live filesystem onto the target — the same image you have been using, so what gets installed is what you tested — and then turns that copy into an ordinary system. The whole install is a file copy: it needs no network, on any supported hardware.

That is why the ISO is around 3 GB. It carries the finished desktop, every graphics vendor's driver and the Broadcom wireless one, because it cannot know what it will be installed onto. Once the hardware is known, the drivers it rules out are removed — an AMD laptop does not keep 900 MB of NVIDIA userspace.

06Write it to a USB stick

Replace /dev/sdX with your stick, and check it is a block device before you write to it — the guard below is not decoration, it is the difference between writing to a disk and writing to a file. 

# confirm which device is the stick
lsblk -o NAME,SIZE,TYPE,RM,MODEL

DEV=/dev/sdX
# refuse to continue unless that really is a block device
[ -b "$DEV" ] || { echo "REFUSING: $DEV is not a block device"; exit 1; }

sudo dd if=starch-x86_64.iso of="$DEV" bs=4M status=progress oflag=direct conv=fsync
sync

Boot it, and the desktop comes up with the installer on top of it.
