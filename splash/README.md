# Boot splash

A Plymouth theme, so the boot shows a splash rather than a wall of kernel and
systemd output. **Escape switches to the text**, which is Plymouth's own
behaviour and the reason for using it rather than just passing `quiet`.

## Escape gives you a blank screen, and that is expected

Escape switches Plymouth to its details view, which renders the boot log. By
the time the splash is up, systemd has finished and the kernel is quiet with
`quiet loglevel=3`, so there is nothing left to render: the details view is
empty and stays empty for the twenty or so seconds Calamares takes to start.
It looks like the machine has hung. It has not — the installer appears.

Adding `systemd.show_status=yes` and dropping the loglevel suppression was
tried and changes nothing, because the problem is not that messages are hidden
but that none are being produced in that window. Filling the gap needs
something drawing to the screen while Calamares loads, which means a compositor
that can paint a background — tried, and reverted, because it cost three
workarounds and a second compositor in the boot path to centre a window.

Without Escape the retained splash covers the gap, which is why
plymouth-quit runs with `--retain-splash`.

## Regenerating the artwork

Nothing here is a binary someone once made and nobody can change. The images
are generated by the scripts next to them, with ImageMagick:

```bash
./logo.sh          # mark + wordmark   -> logo.png  (theme/watermark.png)
./spinner.sh 36    # the ring of dots  -> throbber-NNNN.png
./mock.sh 1920 1080 mock.png   # what a panel will actually show
```

`mock.sh` is the one to run after any change: it composes the real assets at a
real resolution, which is the only way to judge a splash without booting.

## What two-step requires

`lock.png`, `entry.png` and `bullet.png` are not optional, even on a machine
that never asks for a password. two-step loads the lock image when it *shows*
the splash, not when it first needs a dialog — so a theme without them does not
merely lack a dialog, it fails to start, and Plymouth falls back to the text
splash. The symptom is a plain screen with a row of dots and no logo, with
nothing on the console to say why.

`plymouth.debug=file:/dev/ttyS0` on the kernel command line is what finds it:

    00:00:02.153 two-step/plugin.c:1866:show_spl : loading lock image
    00:00:02.153 ply-boot-splash.c:553:ply_b     : can't show splash: No such file or directory

`animation-*.png` frames, by contrast, *are* optional — the `glow` theme ships
none.

## Sizing

Plymouth draws the watermark at its native size; it does not fit it to the
screen. An image sized "large enough for anything" fills the display instead.
This one is 440px tall, which suits 1080p; Plymouth doubles images on a hidpi
output, so designing for 1080p covers 4K too.

The throbber is positioned from the centre of the screen, and the watermark is
anchored at *its* centre — so the throbber has to clear half the logo's height,
not all of it. At `.73` it landed on top of the wordmark.

## The mark

A mountain, since starch is Arch and Arch's logo is a mountain — but drawn as
two open strokes rather than a filled triangle. Arch's logo belongs to Arch;
starch is not Arch upstream and should not wear its badge. The gradient is the
mauve→sapphire the window borders use, at the same 45 degrees.

## Where it is installed

`build.sh` puts the theme in the live image at
`/usr/share/plymouth/themes/starch` and makes it the default; the installed
system is a copy of that image, so it arrives with it. `installer/add-plymouth`
puts the hook in the target's initramfs and `installer/splash-cmdline` adds
`quiet splash` to its boot entries.

It used to live in hyprland-setup, and `install.sh` installed it. It moved
here because that script also runs on machines starch never installed — on
Fedora it was replacing the distro's boot theme and rebuilding every
initramfs.
